# Choice Modeling: MNL vs. DeepMNL vs. Set Transformer

**Research question:** can a set-aware Transformer model customer choice
under changing assortments better than traditional/non-contextual models,
and do better predictions translate into better assortment decisions?

This project has two parts:

1. **A controlled synthetic experiment.** A benchmark with a known,
   injected context effect that plain feature-only models (MNL, and a
   DeepMNL that still scores each item independently) are *structurally*
   unable to see, so the comparison has a ground truth to check against.
2. **A real-data validation pass.** The same three models, the same
   training/eval harness, unchanged, run on real purchase data (the Bakery
   basket dataset) to check whether the Transformer's synthetic-data
   advantage holds up, shrinks, or disappears once the effect isn't
   designed-in.

```
synthetic data (known effect) → MNL / DeepMNL / Set Transformer → comparison
real data (Bakery, no known effect) → same models, same harness → comparison
```

## Why synthetic first

The synthetic benchmark is built so that a plain feature-only choice model
(MNL, or a DeepMNL that still scores each item independently) is
**structurally** unable to fit part of the data — not just less accurate,
but missing an input it would need. See `decisions.md` for the exact
mechanism (an asymmetric-dominance decoy effect) and the sanity checks run
against it.

## Where things stand: synthetic

MNL and DeepMNL both structurally cannot see the injected context effect
and don't (verified). The Set Transformer partially can: it's never worse
than MNL/DeepMNL on log-likelihood and modestly better as the effect
strengthens, but its learned response captures only ~6-50% of the true
effect magnitude and doesn't calibrate to how strong the effect actually
is in a given regime -- a real but incomplete result, not a clean win. See
`decisions.md` (Set Transformer section) for the full finding, numbers,
and working hypothesis for why. The formal, reproducible version of this
comparison is in `results/comparison_report.md`, generated by
`python -m src.train`.

## Where things stand: real data (Bakery)

`src/data/bakery.py` converts basket/subset-selection data (Benson, Kumar
& Tomkins, WSDM 2018) into single-choice training data via a documented
construction (see `decisions.md`) -- there's no known true utility and no
injected effect here, so this reports NLL/accuracy directly rather than
comparing to a Bayes-optimal reference.

**The result: the Set Transformer's synthetic-data advantage disappears
here.** All three models are statistically indistinguishable (NLL spread
0.0004 nats, accuracy spread 0.7 points -- MNL 0.2150, Set Transformer
0.2114, DeepMNL 0.2081). This isn't a mysterious failure to replicate --
it's explicable and was anticipated during the data loader's design (see
`decisions.md`): the choice sets here are built with popularity-weighted
negative sampling, independent of which item is chosen, so there's no
cross-item substitution structure of the kind the synthetic decoy effect
deliberately injects, and nothing for attention over the set to exploit.
The honest conclusion isn't "Transformers don't help on real data" --
it's that whether a set-aware model has *any* advantage depends on
whether the choice-set construction preserves real substitution
structure, which this particular one doesn't. See the "Real-data
validation: Bakery" section of `results/comparison_report.md` (generated
by `python -m src.train_bakery`) for the full numbers, and `decisions.md`
for the complete methodology and reasoning.

## Repo structure

```
src/
├── data/
│   ├── synthetic.py           # synthetic choice data generator (known injected effect)
│   ├── bakery.py               # real-data loader: Bakery baskets -> single-choice format
│   └── external/bakery.txt     # vendored raw Bakery dataset (see external/SOURCE.md)
├── models/
│   ├── mnl.py                  # classical Multinomial Logit
│   ├── deep_mnl.py              # neural MNL (per-item MLP, still no set-context)
│   └── set_transformer.py       # set-aware Transformer (attention over assortment)
├── train.py                    # synthetic pipeline
├── train_bakery.py             # real-data pipeline (same harness, different data loading)
├── evaluate.py
└── utils.py                    # shared harness: featurize, padding, splits, training loop
notebooks/01_exploration_and_comparison.ipynb
tests/
results/comparison_report.md   # synthetic results + a real-data section, both generated
```

## Generating the synthetic benchmark

```bash
python -m src.data.synthetic
```

Writes `data/synthetic_benchmark.csv` (long format: one row per
customer/choice_set/item) and `data/item_universe.csv`. `data/` is
gitignored — regenerate it rather than committing it.

## Running the synthetic pipeline

```bash
python -m src.train
```

Generates the benchmark, trains MNL/DeepMNL/Set Transformer on identical
splits (Set Transformer takes several minutes to reach genuine
convergence), and writes `results/metrics.csv`, `results/decoy_shifts.csv`,
`results/comparison_report.md`, and model checkpoints to `checkpoints/`
(gitignored — rerun rather than committing binary weights).

## Running the real-data validation

```bash
python -m src.train_bakery
```

Loads the Bakery dataset, trains the same three models with the same
harness, and appends a "Real-data validation: Bakery" section to
`results/comparison_report.md` (without touching the synthetic results
already there) plus `results/bakery_metrics.csv` and
`checkpoints/bakery_*.pt`.

## Running tests

```bash
pytest tests/ -v
```

## What's here

- Synthetic data generator with a controllable, injected context effect
- Classical MNL (dual PyTorch/scipy fits, coefficient recovery verified)
- DeepMNL (per-item MLP, structurally still blind to context)
- Set-aware Transformer (self-attention over the choice set)
- Shared training/eval harness + auto-generated comparison report
- Comparison notebook
- Real-data validation pass on the Bakery dataset, same harness

See `decisions.md` for the full design log: every non-obvious choice, the
bugs caught along the way, and the honest findings (including the ones
that didn't come out as cleanly as hoped).
